Правила версионирования Trickster:

Версия обозначает выпуск продукта. Не повышай её автоматически после каждого задания, промпта, коммита или добавленной функции.

По умолчанию сохраняй текущую версию. Накапливай изменения в разделе Unreleased файла CHANGELOG.md.

Используй формат MAJOR.MINOR.PATCH:
— PATCH: выпуск исправлений, доработок UX и небольших совместимых улучшений;
— MINOR: выпуск завершённой значимой возможности или согласованного этапа развития;
— MAJOR: крупный этап зрелости или существенный пересмотр совместимости. Версию 1.0 выпускаем после достижения отдельно определённых критериев готовности.

Сам факт реализации новой функции не требует немедленного выпуска новой версии.

Для незавершённых сборок следующего выпуска используй суффикс -dev, например 0.4.1-dev. Для идентификации конкретного состояния используй короткий Git SHA; не увеличивай номер версии ради различения сборок.

Меняй версию, когда задание явно предусматривает подготовку выпуска или выполнение заранее установленного этапа релизного плана. В остальных случаях можешь предложить номер следующего выпуска в итоговом отчёте, сохранив текущую версию в проекте.

При подготовке выпуска синхронизируй номер в приложении, сборке, упаковке и документации. По возможности используй единый источник версии.
