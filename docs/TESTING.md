# Testing Trickster

Run commands from the repository root after [building](BUILD.md). Create `artifacts` before writing logs. Tests use original synthetic fixtures; optional user assets remain outside Git. Tests can regenerate examples, so inspect `git diff` afterward and keep intentional user edits.

## Regression and desktop checks

```powershell
New-Item -ItemType Directory artifacts -Force
ctest --test-dir build --output-on-failure -j 1
$env:QT_SCALE_FACTOR = '1.5'
.\build\TricksterUXScopeTests.exe -o artifacts/ux-150.txt,txt
.\build\TricksterMVPUItests.exe -o artifacts/mvp-ui-150.txt,txt
.\build\TricksterPhysicsUItests.exe -o artifacts/physics-ui-150.txt,txt
.\build\TricksterNotesTests.exe -o artifacts/notes-150.txt,txt
Remove-Item Env:QT_SCALE_FACTOR
```

`ctest --test-dir build -N` lists the current suites (14 in 0.5.0). GUI suites drive real Qt widgets; a passing numerical suite is not visual animation-quality approval. Notes and Physics UI include physical 1280 x 720 checks. Repeat affected UI checks at scales 1 and 1.5 after layout changes.

Automation exercises the catalog and registered actions, transaction/Undo behavior, dialogs, UI access and protocol. `tests/mcp_client_check.py` additionally uses the optional official Python MCP SDK; see its CLI help and [MCP](MCP.md). Python and that SDK are development/client dependencies, not application requirements.

## Portable runtime

Prepare a new output folder with `package.ps1`, then run:

```powershell
python scripts/test-portable-reliability.py --executable dist/Trickster-local/Trickster.exe --source examples/physics/whole-body-source.trickster --output artifacts/portable-check
```

This owns a separate process with a Windows-system-only PATH and checks empty startup, authenticated 42-tool discovery, model/proxy operations, schema-8 save, GLB/FBX export, MCP Stop and clean close. It removes its temporary connection file. Do not point it at an unsaved interactive session.

## Demos and independent consumers

```powershell
.\build\TricksterMotionDemos.exe examples/motion-tools
.\build\TricksterMuJoCoTests.exe -o artifacts/mujoco.txt,txt
.\build\TricksterPhysicsReplay.exe artifacts/physics-demo/squat.json artifacts/physics-demo/landing.json
python scripts/validate-motion-godot.py --godot 'C:\Tools\Godot\Godot.exe' --basename result --input-dir artifacts/physics-demo/landing --work-dir artifacts/physics-independent/landing --bake-fps 240
```

Replay inputs are generated by MuJoCo tests. The Godot script creates a separate project and checks joints, world matrices and CPU-deformed geometry at key/intermediate times. Its fixed geometry tolerance is 1 mm. Consumer bake FPS, retained tracks and compression settings are part of the experiment; geometry agreement alone cannot certify dynamics. For a 48-FPS demo export use 48-FPS consumer import. Godot's FBX Step conversion is a known failing discontinuity case; do not describe it as passed.

## Scientific physics gate

```powershell
.\build\TricksterReliabilityTests.exe -o artifacts/reliability-tests.txt,txt
python scripts/check-physics-reliability.py
python scripts/report-physics-reliability.py --output artifacts/reliability-publication --publish-examples
```

The last command writes release materials under ignored `artifacts`; it does not add large reports to `docs` or `examples`. Full reliability tests include 12 imported full-body amplitude/duration variants. `TRICKSTER_RELIABILITY_QUICK=1` omits variants and is not a complete acceptance run. The harness allows 20 minutes per test function and 30 minutes per suite.

**The acceptance checker intentionally returns nonzero while scientific gates remain open.** Regression success must not replace this gate. Compare before/after on the same model, estimator, grid and scope; retain failed runs. [Fixed tolerances](PHYSICS_ACCEPTANCE.md) and [reliability methods](PHYSICS_RELIABILITY.md) define the interpretation and external-consumer follow-up.

## Performance

```powershell
.\build\TricksterMotionBenchmark.exe artifacts/performance-100.json
$env:QT_SCALE_FACTOR = '1.5'
.\build\TricksterMotionBenchmark.exe artifacts/performance-150.json
.\build\TricksterMotionBenchmark.exe artifacts/dense-60.json dense-textured 60
Remove-Item Env:QT_SCALE_FACTOR
```

Run without concurrent builds/tests. Compare CPU fallback and GPU skinning in the same build across six synthetic fixtures. Retain hardware, actual GL context, resolution, DPI, source identity, warmup and all samples. CPU paint, asynchronous GPU queries, seek/readback and unique Qt playback swap ordinals measure different things; swaps are not display scan-out. Do not promise universal speedups or GPU physics.

## Records

Keep new logs under `artifacts` and publish reviewed evidence with the corresponding release. [0.5.0](releases/0.5.0.md) records its clean checks. Earlier command logs, audit tables, scalar reports and measurement context are preserved in the [historical evidence archive](https://github.com/Atmosaero/Trickster/releases/download/v0.5.0/Trickster-0.5.0-validation-evidence.zip). Those records identify different builds and are not one combined test run.
